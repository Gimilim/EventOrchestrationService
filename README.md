# EventOrchestrationService
Данный проект реализует API для работы с событиями.
Используется актуальная версия .net (10) на момент реализации проекта

Структура проекта:

/Models -- модели проекта
/Controllers -- контроллеры проекта
/Data -- хранение данных и настройки их хранения
/BackgroundServices - фоновая обработка
/DTOs -- ДТО модели проекта
/Entities -- модели БД
/Migrations -- миграции проекта

Подключенные технологии:
-Используется fluentValidation (в основном "на вырост")
-Подключены Moq и xUnit для тестов
-Для интеграционных тестов используется Testcontainers.PostgreSql (Обязательно нужен докер для прогона интеграционных тестов!)
-Есть планы на переход на OpenApi вместо сваггера
-PostgreSQL для хранения данных
-Юнит тесты крутятся на InMemory SQLite
-Интеграционные на 17 версии Постгре

Общая информация:
-Сервис разделен на 3 проекта: юнит тесты, интеграционные тесты и сам апи слой
-Реализован глобальный перехватчик ошибок для всех исключений
-Реализована пагинация для запроса всех событий
-Методы базово покрыты тестами
-Добавлена фоновая обработка
-При первом запуске будет создана БД через миграцию
-Реализован паттерн репозиторий для разделения ответственности
-Реализована автоматическая накатка всех непримененных миграций при запуске проекта

События:
События содержат поля TotalSeats и AvailableSeats, которые отвечают за набор мест на событии и количество мест, которые в данный момент доступны для бронирования.

Общая концепция:
-Возможность создавать, редактировать, удалять, обновлять события, а так же делать бронирование (с фоновой обработкой)
на эти события.
Фоновая обработка перехватывает все бронирования и обрабатывает их. На текущий момент заглушка, имитирующая долгую деятельность

### Основные эндпоинты

Бронирования:
- `POST /events/{id}/book` — создать бронирование, возвращает `202 Accepted` с заголовком `Location: /bookings/{id}` и телом `{ id, eventId, status }`.
Так же теперь может возвращать 409 Conflict при отсутствии мест;
- `GET /bookings/{id}` — статус бронирования, возвращает `200 OK` с `{ id, status }`


- ### Фондовая обработка бронирований

`BookingBackgroundService` — фоновая служба, которая обрабатывает бронирования в асинхронном режиме.

**Как работает:**
- Каждые 5 секунд сервис запрашивает из БД все бронирования со статусом `Pending`
- Обработка выполняется параллельно через `Task.WhenAll` для повышения пропускной способности
- Для каждого бронирования имитируется долгая обработка (10 секунд) — задержка выполняется параллельно для всех заявок
- После задержки проверяется существование события: если событие не найдено — бронь отклоняется (`Rejected`), если найдено — подтверждается (`Confirmed`)
- При возникновении ошибки бронь отклоняется, а место возвращается в пул через `ReleaseSeats()`

**Примитивы синхронизации:**
- `SemaphoreSlim` — защищает запись в хранилище при обновлении статусов. Захватывается после имитации задержки,
чтобы задержки выполнялись параллельно, а блокировка занимала минимальное время. В отличие от `lock`, поддерживает `await` внутри критической секции
